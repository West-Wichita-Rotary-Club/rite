## Proposed Change

### Principle: IX. Production Architecture Is .NET API Plus Standalone React (NON-NEGOTIABLE)

> Build an ASP.NET Core MVC/Web API backend backed by SQLite and a standalone React site that
> calls the API. Authentication is a developer's choice sized to the program — a simple
> credential or magic-link scheme is sufficient for this small, volunteer-run exchange; adopt
> OpenID Connect (e.g. Auth0) only if a real future need (SSO, a second consuming application,
> compliance requirement) justifies the added complexity.

**Rationale**: RITE is a volunteer-run program with a small, known user base (teachers, host
families, Rotary leaders, coordinators, school administrators — Principle V). A third-party
OpenID Connect provider adds cost, an external dependency, and operational complexity (provider
account, redirect configuration, token handling) disproportionate to that scale. ps-009 was
already scoped toward simple auth before this conflict surfaced; this amendment aligns the
constitution with the actual, developer-chosen direction rather than forcing ps-009 to adopt
unneeded complexity to satisfy an aspirational mandate nothing else in the project currently
depends on.

**MUST Requirements:**

- Authentication must exist and must protect account/profile/claim/memory data from
  unauthenticated access once a real backend (ps-009) ships.
- If a future need justifies OpenID Connect, it replaces the simple scheme deliberately, as its
  own decision — not silently, and not by default.

**SHOULD Recommendations:**

- Prefer the simplest scheme that meets the MUST above (credential or magic-link) unless a
  concrete requirement (SSO, a second consuming application, a compliance obligation) is
  identified.
