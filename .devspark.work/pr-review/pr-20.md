## Deployment & Handoff Notes

### Deployment Notes

- `src/Rite.Api/Data/ContentSeeder.cs` initializes the schema with `EnsureCreatedAsync`, which does not add columns to an already-existing SQLite file. `Account.IsCoordinator`/`IsActive` are new columns, so a VM that already has a `rite.db` from an earlier deployment would need that file replaced or migrated before this change takes effect. This is pre-existing architecture (not introduced by this PR — ps-009's columns had the same property) and is currently moot: per the README, production hosting (ps-008) has not been deployed yet, so no live `rite.db` exists to break. Worth a decision before ps-008's first deploy, not before this PR merges.

### Observations

- A coordinator can deactivate their own account (including, if they are the only coordinator, locking every coordinator out of `/coordinator` and of any session). Recovery would require the same direct-database edit this feature's own Material Exclusions already accept as the only way to grant `IsCoordinator` in the first place — so this doesn't introduce a new class of risk beyond what the feature already designed around. Not a finding; worth a one-line UI guard later if it proves to bite someone in practice.
- `ReactivateUserAsync`'s 404-for-unknown-id path has no dedicated test, unlike `DeactivateUserAsync`'s. The two methods are structurally identical (same `FindAsync` + null check), and that pattern is already proven by the sibling test — simple delegation, not a coverage gap (§4C Test 6 / PRD3 proportionality).
- The preflight script's `risk.knowledge.status: absent` and the `\r`-suffixed paths in its `unmapped_files`/`risk.files` output look like a Windows line-ending artifact in the script itself (every path in this PR's output carries a trailing `\r`), not a defect in this PR's code or `.knowledge/` content. Flagged here for whoever maintains `.devspark/scripts/`, not as a reason to doubt this PR's Knowledge consistency (checked directly above instead).
