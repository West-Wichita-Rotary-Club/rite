### DELTA4 — Durable content cites `.archive/` paths as provenance (HIGH)

**Outcome: resolved (2026-11-15, same day).** All seven citations below were rewritten to restate
the underlying fact in prose, without depending on the archived path. Re-scanned repo-wide
(excluding `.archive/`, `.devspark/`, and this report's own description of the finding) — zero
remaining `.archive/` citations in durable content. `AGENTS.md`/`CLAUDE.md`'s mentions were
confirmed, on re-check, to describe the `.archive/` convention itself (not cite archived content as
evidence) and were left as-is, per the distinction already drawn below.

**Principle / rule**: Command Preamble Contract §0 — *"No DevSpark command reads, lists, enumerates, or globs `.archive/`, under any circumstance. It is a write-only destination... commands move content into it and never look back."* §5 Step 5.5 extends this to any durable reference: *"an archived path is just as forbidden as a live planning path, since it still points at ephemeral state that may be pruned or renumbered."*

**Issue**: Seven durable files cite `.archive/bold-docs/...` paths as provenance/evidence for current claims (not merely describing the `.archive/` convention itself, which is fine — these cite *specific archived files* as the source of a current fact):

| File:Line | Citation |
|-----------|----------|
| `.knowledge/governance/constitution.md:3,5,25,51,103-104,108` | Cites `.archive/bold-docs/backbone.md`, `.../features/0005.../spec.md`, `.../features/0001.../prototype/`, `.../system/creative-brief.md` as the basis for migration provenance and the "supersedes" claim |
| `docs/content/resources.json:4` | Cites `.archive/bold-docs/features/0003.../resource-candidates.md` and `.../0004.../content-candidates.md` as proof of product-owner sign-off |
| `docs/content/resources.schema.json:58` | Same two citations, as the `reviewPolicy.note` |
| `docs/content/stories.json:4` | Cites `.archive/bold-docs/features/0004.../content-audit.md` as the basis for which stories were retired |
| `docs/README.md:28` | Same two resource-approval citations |
| `docs/styles.css:2` | Cites `.archive/bold-docs/features/0001.../prototype/_ds/.../typography.css` as the source of the imported fonts |

**Intent**: these citations exist to answer "why was this approved / where did this come from" — a legitimate question, but the archive is explicitly not a place any command (or reader relying on command-maintained accuracy) may resolve, so the citation itself is unreliable the moment anything in `.archive/` is pruned or renumbered.

**Recommendation**: Replace each citation with either (a) a plain-prose restatement of the fact that doesn't depend on the archived file still existing at that path (e.g., "approved by the product owner during feature 0003/0004" without the path), or (b) if the provenance detail still matters long-term, promote the relevant fact into a durable `.knowledge/` document and cite that instead. Do not re-point these at `.archive/` again.

**Note**: `AGENTS.md` and `CLAUDE.md` also mention `.archive/bold-docs/`, but only to describe what the `.archive/` directory *is* and that it's never read automatically — that's the same kind of self-referential description the Command Preamble Contract itself uses, not a provenance citation, so it isn't included above.
